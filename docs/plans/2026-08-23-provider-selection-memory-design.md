# Provider 选择记忆设计

## 目标

在不改变现有 Provider 请求架构的前提下，使用浏览器 `localStorage` 记住用户最后一次选择的 Provider。用户再次打开页面时恢复仍然存在的选项，并为它们创建全新的“尚未翻译”卡片。

本次不新增 Google 或 Bing 浏览器直连 Provider。

## 存储格式

- 存储键：`vast-translator:providers`
- 存储值：Provider ID 组成的 JSON 数组，例如 `['google', 'bing', 'agnes-2-5']`
- 只保存 Provider ID，不保存译文、请求、错误、折叠状态、复制反馈或请求快照。

## 恢复规则

1. 存储项不存在时，默认选择 Google 和 Bing。
2. 合法数组恢复为当前仍存在的 Provider：去重、过滤未知或已下架 ID，并按页面固定顺序排列。
3. 合法空数组 `[]` 表示用户明确取消全部选择，刷新后继续保持全不选。
4. 如果合法数组中的所有 ID 都已下架，过滤结果为空，保持全不选。
5. JSON 损坏或存储值不是数组时，回退到默认 Google 和 Bing。
6. 读取 `localStorage` 抛出异常时，回退到默认 Google 和 Bing，不让页面报错。
7. 恢复后的 Provider 只创建 idle 卡片，不自动发起翻译请求。

## 写入规则

每次勾选或取消 Provider 后立即保存完整的新选择。`localStorage.setItem()` 失败时，当前会话中的选择仍然生效，不显示阻断性错误。

## React 与水合

沿用现有布局偏好的 `useSyncExternalStore` 模式，使用稳定的字符串快照避免服务端渲染与客户端水合不一致。Provider 选择使用独立存储键，不迁移或改写现有布局偏好。

组件内部继续维护会话状态，以便存储写入失败时仍能正常交互。存储快照变化时，将外部选择与当前卡片状态做增量同步：

- 新增 Provider：按固定顺序创建 idle 卡片，不自动请求。
- 移除 Provider：中止该 Provider 请求，清理卡片、折叠状态与复制反馈。
- 仍然存在的 Provider：保留当前卡片及结果，不全部重建。

## 跨标签页同步

监听 `storage` 事件。同一浏览器的其他标签页修改选择后，当前页面同步增删 Provider。同步删除 pending Provider 时必须中止对应请求；迟到响应不得恢复卡片。

## 测试范围

- 无存储时默认选择 Google、Bing。
- 选择变化后写入存储，重新挂载后恢复为 idle 卡片且不发请求。
- 合法空数组保持全不选。
- 未知或已下架 ID 被过滤。
- 重复 ID 去重并恢复固定顺序。
- 所有保存项均下架后保持全不选。
- 非法 JSON、非数组、读取异常回退默认值。
- 写入异常不影响当前会话。
- 跨标签页事件增删卡片，并独立中止被移除 Provider 的请求。
- 不影响布局存储与现有单卡、批量、取消和迟到响应行为。
