# 渐进式翻译结果与单 Provider 重试设计

## 目标

- 点击“开始翻译”后并行调用所有已选 Provider，哪个先完成就先展示哪个结果。
- 失败结果可单独重试，不影响其他 Provider。
- Agnes 不设置应用层超时，仅受上游网络、客户端取消及 Vercel 平台时限约束。

## 请求模型

前端为每个已选 Provider 各发送一个 `POST /api/translate` 请求，每次请求的 `providers` 只包含一个 Provider。这样无需引入 SSE 或 NDJSON，也能逐项更新结果，并天然支持单项重试。

开始翻译时保存不可变请求快照：原文、源语言、目标语言和 Provider 顺序。所有结果卡立即进入加载状态。请求完成后只更新对应卡片，卡片顺序始终按提交顺序保持稳定。

## 单项重试

失败结果卡显示“重试”和“折叠/展开”按钮，不显示复制按钮。重试复用本批次提交时的原文与语言快照，而不是输入框后来编辑的内容。重试期间只有该卡进入加载状态，其他结果和折叠状态保持不变，并阻止同一 Provider 重复重试。

## 状态与取消

只要任一 Provider 仍在加载，本批次保持进行中，语言和 Provider 选择继续锁定；已完成卡片立即可复制或折叠。输入文本仍可编辑。新一批翻译会取消上一批未完成请求，重建请求快照并重置卡片状态，避免旧响应污染新结果。

## 超时

- Google、Bing、Azure：继续使用 12 秒应用层硬超时。
- Agnes 2.0、Agnes 2.5：不设置应用层超时。
- 所有 Provider 均响应客户端取消。
- Vercel 或上游终止请求时，该 Provider 独立显示失败，可手动重试。

## 测试重点

- 快慢 Provider 的结果按完成时间渐进显示，但卡片顺序不变。
- 单项失败不影响其他 Provider。
- 重试只调用失败 Provider，并使用原请求快照。
- 重试期间仅目标卡加载，且阻止重复重试。
- 新批次不接收旧批次响应。
- Agnes 不创建应用层超时计时器，Google/Bing/Azure 仍保持 12 秒超时。
