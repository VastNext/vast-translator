# 独立 Provider 卡片设计

## 目标

将 Provider 卡片从统一批次的展示结果改为可独立执行的翻译单元。用户临时增加 Provider 时，无需重新调用已经完成的 Provider，从而减少多余请求和外部服务资源消耗。

## Provider 选择行为

- 勾选一个尚无卡片的 Provider，立即按固定 Provider 顺序插入“尚未翻译”卡片，但不自动发起请求。
- 取消勾选 Provider，立即移除对应卡片和快照。
- 如果被移除的卡片正在请求，则中止该请求；迟到响应不得恢复卡片。
- 再次勾选时创建全新的“尚未翻译”卡片，不恢复旧结果。

## 卡片状态与操作

每张卡片独立维护以下状态：

```text
尚未翻译 → 正在翻译 → 翻译成功
                    ↘ 翻译失败
```

按钮文案随状态变化：

| 状态 | 文案 | 行为 |
|---|---|---|
| 尚未翻译 | 翻译 | 首次调用该 Provider |
| 正在翻译 | 正在翻译 | 禁用，防止重复请求 |
| 翻译成功 | 重新翻译 | 重新调用该 Provider 并替换结果 |
| 翻译失败 | 重试 | 再次调用该 Provider |

“翻译”“重新翻译”和“重试”均使用点击当下的输入框文本、源语言和目标语言。请求开始时把这些值保存为该卡自己的不可变快照。单卡操作只改变目标卡片，不影响其他卡片的结果、折叠或复制状态。

## 批量按钮

主按钮继续作为所有已选 Provider 的显式批量操作：

- 没有任何已结算结果时显示“开始翻译”。
- 已有任意成功或失败结果时显示“全部重新翻译”。
- 任一卡片正在请求时显示“正在翻译”并禁用。

点击主按钮时，所有当前已选卡片使用同一份当前文本和语言分别发起独立请求。已成功、失败和尚未翻译的卡片都会重新执行。

## 独立请求模型

每张卡片保存 Provider、状态、结果、上一次请求快照和当前请求标识。请求控制器按 Provider 独立存放，不进入 React state。

每次执行单卡请求：

1. 中止该卡已有请求。
2. 创建新的请求标识和 `AbortController`。
3. 保存当前输入和语言快照。
4. 将该卡切换为正在翻译。
5. 发送只包含该 Provider 的请求。
6. 响应返回时确认卡片仍存在且请求标识仍匹配。
7. 更新成功或失败结果；过期响应直接忽略。

组件卸载时中止全部卡片请求。批量执行复用同一个单卡执行函数，不建立第二套请求逻辑。

## 编辑与锁定规则

- 单卡请求期间输入框、语言选择和 Provider 选择仍可编辑。
- 单卡正在请求时，仅该卡操作按钮禁用。
- 任一卡片请求期间，批量按钮禁用，避免批量操作与单卡请求重叠。
- 当前输入为空时，所有卡片执行按钮和批量按钮禁用，但已有结果继续保留。

## 结果上下文提示

成功或失败卡片保留其最近一次请求快照。当当前输入文本、源语言或目标语言与该快照不一致时，卡片耗时旁显示“基于较早内容”。当前编辑内容再次与快照一致时，提示消失。

## 无障碍

- 尚未翻译卡片提供明确状态文本。
- 卡片按钮的可访问名称包含 Provider 和动作，例如“使用 Agnes 2.5 翻译”“重新执行 Google 翻译”“重试 Bing 翻译”。
- 请求中卡片使用 `aria-busy`，完成后继续逐卡播报成功或失败。
- “基于较早内容”同时提供可见文本和可被辅助技术读取的语义。

## 测试范围

1. 勾选 Provider 立即插入尚未翻译卡，不产生请求。
2. 新卡“翻译”只请求该 Provider，并使用当前文本和语言。
3. 成功卡显示“重新翻译”，失败卡显示“重试”。
4. 单卡操作不改变其他卡片和折叠状态。
5. 取消 Provider 立即移除卡片并中止请求，迟到响应不可恢复卡片。
6. 重新勾选创建全新卡片，不恢复旧结果。
7. 卡片快照与当前编辑内容不同时显示“基于较早内容”。
8. 主按钮根据状态显示“开始翻译”或“全部重新翻译”，并操作所有已选卡片。
9. 空输入时禁用执行按钮但保留结果。
10. 单卡请求期间仍可编辑输入、语言和 Provider。
11. 防止单卡重复请求及批量/单卡请求重叠。
12. 组件卸载中止所有独立请求。
